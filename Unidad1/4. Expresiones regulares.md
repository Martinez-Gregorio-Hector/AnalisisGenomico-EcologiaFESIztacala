# Conceptos fundamentales sobre la estructura, variables internas y funcionamiento de los programas AWK

## Un poco de definción

¿Qué es AWK?

AWK es un lenguaje de programación de propósito específico, diseñado en los años 70 por Aho, Weinberger y Kernighan (de ahí su nombre: Aho, Weinberger, Kernighan).

Se usa principalmente en Linux/Unix para:

* Procesar texto y archivos estructurados en columnas.
  
* Filtrar y transformar datos.
  
* Generar reportes rápidos.

En pocas palabras: es como un “Excel en la terminal” para datos en texto plano.

## Siguiendo con AWK

De manera globla, al intérprete de comandos **awk** se le pasan dos piezas de datos:

* un fichero de órdenes o programa
  
* uno o más archivos de entrada.
  
Un fichero de órdenes (que puede ser un fichero real, o puede ser incluido en la invocación de **awk** desde la línea de comandos) contiene una serie de sentencias que le indican a **awk** cómo procesar el fichero de entrada. Es decir contiene el programa escrito en sintaxis AWK.

```
awk ‘programa_AWK’ archivo1 archivo2 …
awk -f ‘archivo_con_código_AWK’ archivo1 archivo2
```

El archivo primario de entrada es normalmente texto estructurado con un formato particular, por defecto archivos con campos separados por espacios o tabuladores (tablas).

## FILENAME

Si se especifican varios archivos, éstos se procesan en el orden en el que se le pasan a **awk**. El nombre del archivo que está siendo procesado por **awk** queda guardado en la variable interna FILENAME.

## Registros y las variables asociadas RS, FNR, NR

**awk** procesa los archivos en unidades conocidas como registros (records), que se procesan acorde a las órdenes del programa, registro por registro.

Por defecto, los registros se separan con saltos de línea (RS=“\n”). Es decir, por defecto **awk** modela tablas, en las que cada fila corresponde a un registro.

El separador de registros, guardado en la variable interna **RS**(Record Separator) se puede modificar asignándole un valor que puede ser una expresión regular. Ello le permite al programador modelar con gran precisión y versatilidad la estructura de los registros.

Así por ejemplo, si nuestros datos están contenidos en un archivo de secuencias multifasta, puede ser muy conveniente definir el separador de registros de la siguiente manera: RS=“>”, ya que cada nuevo registro (secuencia en este caso) inicia con el símbolo ‘>’

La variable interna **FNR** cuenta el número de registros del archivo en procesamiento. Esta variable se reinicia a 0 cuando **awk** va a procesar un nuevo archivo.

La variable interna **NR** cuenta el número de registros que ha procesado **awk** de manera acumulativa (nunca se reinicia si lee un nuevo archivo)

## Los campos de un registro y las variables FS, NF, $0, $1 y $n

Por defecto **awk** procesa automáticamente cada registro (acorde al valor asignado a **RS**), separándolo en campos delimitados por espacios, tabuladores o saltos de línea, que **gawk** define internamente como 𝐹𝑆=" ".

* Cada campo del registro en procesamiento es guardado en las variables internas $1 … $n

* El contenido del registro completo está guardado en $0 y el número total de sus campos en NF

Noten que las variables $0, $1 … $n son las únicas en AWK que siempre van precedidas del símbolo $.

* Define exactamente qué está haciendo el programa, es decir, interpreta o explica con precisión la salida observada
  * parseo estándar de un registro y sus campos en **gawk**

“Parsear” = analizar sintácticamente un texto o datos, es decir, leerlos y descomponerlos en partes comprensibles según unas reglas (gramática, delimitadores, formato, etc.). Ejemplo: leer un archivo CSV y separar cada línea en columnas usando la coma como separador.

```
echo -e  " campo1  campo2\tcampo3,-#%...  " | awk '{print NF, "["$1"]"}'
echo -e  " campo1  campo2\tcampo3,-#%...  " | awk '{print NF, "["$3"]", "["$1"]"}'
echo -e  " campo1  campo2\tcampo3,-#%...  " | awk '{print NF, $NF}'
echo -e  " campo1  campo2\tcampo3,-#%...  " | awk '{print NF, "["$0"]"}'

```

## Ejemplos genéricos de estructura de programas AWK

* Un programa AWK típico consiste en una serie de líneas, cada una de la forma:

/patrón/ { acción }, donde:

* la acción por defecto es imprimir {print}. Como explicamos en el ejemplo anterior, **print** imprime los argumentos que se le pasan separados por comas, dejando por defecto un espacio sencillo entre ellos (OFS=” “). Las variables se escriben sin comillas, los caracteres literales entre comillas dobles. Si omitimos las comas entre argumentos, se concatenan, como muestra la salida de ‘{print NF, “[”$1”]”}’
* patrón es una expresión regular, como explicaremos con mayor detalle en una sección posterior
* acción es una orden o programa, que puede ser todo un script te AWK de cientos o miles de líneas

**awk** lee línea por línea el fichero de entrada. Cuando encuentra una línea que coincide con el patrón, ejecuta la(s) orden(es) o programa indicadas en acción.

* Para llamar a **awk** desde la línea de comandos, usaríamos una sintaxis de este tipo:

  
```
awk ‘CODIGO AWK’ ARCHIVO_A_PROCESAR
```

* para usarlo en una tubería de **shell**, conecta el **STDOUT** de un programa al **STDIN** de **awk**
 mediante **|**:

```
programaX | awk ‘CODIGO AWK’ > output_file.txt
```

## Formas alternativas del código AWK y uso de bloques BEGIN{}, END{}

Además del ejemplo genérico /patrón/ { acción } presentado en la sección anterior, a **gawk** se le pueden pasar las siguientes estructuras de código alternativo para controlar el comportamiento del intérprete de comandos:

* BEGIN { acción } Ejecuta las órdenes de acción al comienzo de la ejecución, antes de que los datos comiencen a ser procesados. Aquí inicializamos variables globales como RS, FS, OFS …

* END { acción } Similar a la forma previa, pero ejecuta las órdenes de acción después de que todos los datos sean procesados, por ejemplo para imprimir estadísticas de resumen después de haber analizado los campos de cada registro.
  
* /patrón/ Imprime las líneas que contienen al patrón.
  
* { acción } Ejecuta acción por cada línea en la entrada.

Cada una de estas formas pueden ser incluidas varias veces en un archivo o **script** de 𝐴𝑊𝐾. El 𝑠𝑐𝑟𝑖𝑝𝑡 es procesado de manera progresiva, línea por línea, de izquierda a derecha. Entonces, si hubiera dos declaraciones 𝐵𝐸𝐺𝐼𝑁, sus contenidos serán ejecutados en orden de aparición. Las declaraciones 𝐵𝐸𝐺𝐼𝑁 y 𝐸𝑁𝐷 no necesitan estar en forma ordenada.

## Inicialización de variables en bloque BEGIN{} para modelar adecuadamente la estructura de un registro

Como indicábamos anteriormente, 𝐴𝑊𝐾 permite al programador modelar con gran precisión y versatilidad la estructura de los registros mediante la asignación de los valores más apropiados a las variables 𝑅𝑆, y 𝐹𝑆. Esto se hace generalmente dentro de un bloque de inicialización BEGIN{}, como se muestra en los ejemplos que siguen. Revisemos nuevamente algunos de los ejemplos usados anteriormente con los valores por defecto de 𝑅𝑆, 𝐹𝑆 y 𝑂𝐹𝑆.

## Análisis de archivos con campos separados por tabuladores (tsv)

Mejorando el modelado de la estructura de los registros del archivo mini_tabla.tsv

```
head -5 mini_tabla.tsv
```

En base a la salida anterior, ¿cuál piensas que era la intención del programador y qué piensas está mal en el código que sigue?

```
awk '{print $1, $2, $4, $NF}' mini_tabla.tsv
```

Obviamente debemos cambiar el valor por defecto de FS=[[:space:]]+, regexp que se ajusta a uno o más espacios, tabuladores y saltos de línea a esta otra FS=“ qué sólo empareja con tabuladores.

```
awk 'BEGIN{FS="\t"} {print $1, $2, $4, $NF}' mini_tabla.tsv

```

La salida del programa anterior la podemos mejorar indicando que el separador de campo de la salida 𝑂𝐹𝑆 sea también un tabulador, para respetar así la estructura original del archivo de entrada.


```
awk 'BEGIN{FS="\t"; OFS=FS} {print $1, $2, $4, $NF}' mini_tabla.tsv

```

Excelente, ya hemos modelado adecuadamente un archivo tabular. Ahora nuestro código AWK responderá adecuadamente a nuestras intenciones, es decir, la sintaxis permite modelar la estructura de los datos para que se ajuste a la semántica del programa.

```
awk 'BEGIN{FS="\t"; OFS=FS} /Pseudomonas/ {print $1, $2, $4, $NF}' mini_tabla.tsv
```

# Expresiones regulares

Una expresión regular es una plantilla de patrón que se define y que una utilidad de Linux utiliza para filtrar texto.

Una utilidad de Linux (como el editor sed o el programa gawk) compara el patrón de la expresión regular con los datos a medida que estos fluyen hacia la utilidad. Si los datos coinciden con el patrón, se aceptan para su procesamiento. Si no, se rechazan.

El patrón de expresión regular utiliza caracteres comodín para representar uno o más caracteres en el flujo de datos. 
En Linux, existen numerosos casos en los que se puede especificar un carácter comodín para representar datos desconocidos. 

## Tipos de expresiones regulares

El mayor problema con el uso de expresiones regulares es que no existe un único conjunto. Diversas aplicaciones utilizan distintos tipos de expresiones regulares en el entorno Linux. Estas incluyen aplicaciones tan diversas como lenguajes de programación (Java, Perl y Python), utilidades de Linux (como el editor sed, el programa gawk y la utilidad grep) y aplicaciones comunes (como los servidores de bases de datos MySQL y PostgreSQL).

Una expresión regular se implementa mediante un intérprete de expresiones regulares (regular expression engine). Un intérprete de expresiones regulares es el software subyacente que interpreta los patrones de expresiones regulares y los utiliza para encontrar coincidencias de texto. En el mundo Linux existen dos motores de expresiones regulares populares:


■ El intérprete de expresiones regulares básicas (BRE) de POSIX

■ El intérprete de expresiones regulares extendidas (ERE) de POSIX

La mayoría de las utilidades de Linux, como mínimo, cumplen con las especificaciones del intérprete BRE de POSIX y reconocen todos los símbolos de patrón que define. Desafortunadamente, algunas utilidades (como el editor sed) solo cumplen con un subconjunto de las especificaciones del intérprete BRE. Esto se debe a limitaciones de velocidad, ya que el editor sed intenta procesar el texto del flujo de datos lo más rápido posible.

El intérprete ERE de POSIX se encuentra a menudo en lenguajes de programación que utilizan expresiones regulares para el filtrado de texto. Proporciona símbolos de patrón avanzados, así como símbolos especiales para patrones comunes, como la coincidencia de dígitos, palabras y caracteres alfanuméricos. El programa gawk utiliza el intérprete ERE para procesar sus patrones de expresiones regulares. Debido a la gran variedad de maneras de implementar expresiones regulares, resulta difícil presentar una descripción única y concisa de todas las posibles. Las siguientes secciones analizan las expresiones regulares más comunes y demuestran cómo utilizarlas en el editor sed y en el programa gawk.
